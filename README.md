# EcoLogicDev

Платформа озеленения Павлодара: React/TypeScript/Vite + FastAPI. Бюджет инфраструктуры 0 ₸. Карта реальная; свойства демонстрационных участков синтетические, расценки саженцев взяты из открытых прайсов. Это MVP с экспертными расчётами, не результат городского обследования.

## Быстрый запуск Windows
Требуются Node.js 22+ и Python 3.12+. Все команды выполняются из этой папки.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm.cmd ci
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:
```powershell
npm.cmd run dev
```
Открыть http://127.0.0.1:5173 . API: http://127.0.0.1:8000/api/docs . После установки можно запускать оба процесса через `powershell -File scripts/start.ps1`.

Для просмотра собранной версии: `npm.cmd run build`, затем `npm.cmd run preview`; адрес http://127.0.0.1:4173/ . API должен работать на 8000. На момент передачи локальная production-версия и API запущены. AI-ключ находится только в памяти текущего процесса; после перезапуска его нужно передать заново через окружение или скрытый ввод.

Если Python отсутствует в PATH, можно использовать установленный Python или bundled runtime Codex: `C:\Users\DjanGo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`.

## Аккаунты и администратор
Локальная email/password регистрация включена по умолчанию; пароли scrypt, непрозрачные HttpOnly сессии, CSRF, 7 дней. Почтовое подтверждение/восстановление без почтового сервиса не заявляется работающим. Firebase-вход можно включить через `VITE_FIREBASE_AUTH=true`, включив Email/Password и разрешённые домены в Firebase Console. API проверяет подпись, audience, issuer и email_verified, затем выдаёт свою cookie. Клиентская Firebase-конфигурация не содержит серверных секретов. Analytics по умолчанию отключена.

Создание администратора — вручную на сервере, пароль запрашивается скрыто:
```powershell
.\.venv\Scripts\python.exe -m backend.admin --email admin@example.com --name Admin
```
Нет встроенного администратора, публичного пароля или возможности самоназначения роли. Пользователь видит только свои проекты; специалист — свои и явно назначенные. Администратор управляет пользователями, справочниками и слоями. Назначение проекта специалисту пока выполняется оператором в базе; отдельного UI назначения нет.

## AI без расходов
`OPENROUTER_API_KEY` задаётся только в окружении backend или в игнорируемом локальном `.env`. В браузер ключ не передаётся. Не публикуйте `.env`. Можно запускать `scripts/serve.py --stdin-env` с одной JSON-строкой через stdin для временного ключа без записи на диск.
`AIModelRouter` получает актуальный каталог, выбирает только `:free`, проверяет нулевые цены всех тарифных полей, задаёт `provider.max_price=0`, пытается до трёх моделей, обрабатывает 429 и `Retry-After`. Максимум 40 попыток/сутки для сервера, 4 вопроса/час гостю и 12 пользователю. Ограничители предполагают один процесс/реплику; для горизонтального масштабирования нужен атомарный Redis/SQL лимитер.
Модель получает заново рассчитанный серверный контекст, не клиентские численные результаты. Её текст — объяснение; авторитетные численные данные находятся в таблицах плана. При отсутствии ключа/квоты возвращается честный статус, остальные функции работают.

## Бесплатная публикация
Сначала локальный запуск и проверки; затем подключение аккаунтов владельца. Репозиторий/токены/пароли не запрашиваются в чате. Реальный публичный сайт пока не считается опубликованным.

1. PostgreSQL: создать Neon Free, установить PostGIS при необходимости, взять pooled connection string и задать `DATABASE_URL=postgresql+psycopg://...`. Не использовать SQLite на Render: диск эфемерен. Первые таблицы/версия схемы создаются идемпотентно при старте; перед будущими миграциями делать резервную копию. PostGIS-расширение: `migrations/001_postgis.sql`.
2. API: Render Free через `render.yaml`/Dockerfile. Задать `DATABASE_URL`, точный `ALLOWED_ORIGINS`, `ENVIRONMENT=production`, `COOKIE_SECURE=true`, `OPENROUTER_API_KEY` как secret, один worker. Не подключать платный план/автопополнение. Проверить `/api/health`.
3. Клиент: Vercel Hobby (некоммерческий личный хакатон) или Firebase Hosting Spark. `npm ci && npm run build`, каталог `dist`. Для прямого обращения к API задать `VITE_API_URL=https://ваш-api` **и обеспечить same-site домены для cookie**. Предпочтительнее проксировать `/api` на backend через хостинг, сохранив единый origin. В Vercel добавьте первым rewrite `/api/:path*` → `https://ваш-api/api/:path*` в `vercel.json`; не публикуйте до подстановки реального адреса. Тогда `VITE_API_URL` оставьте пустым. Firebase Hosting без платных Functions не проксирует внешний Render: для этой схемы нужны same-site домены или другой reverse proxy.
4. Указать точный frontend-origin в API, без wildcard. Для проксируемого API браузерный Origin сохраняется. Не включать доверие `X-Forwarded-For` без настройки доверенного reverse proxy; `TRUST_PROXY=true` допускается только за контролируемым прокси. По умолчанию лимиты по IP могут быть общими для прокси, что безопасно, но строже.
5. Проверить прямые маршруты, регистрацию, CSRF, сохранение и открытие проекта, запрет чужого проекта, роли, PDF/Excel, AI и ошибку квоты.

Render Free засыпает через 15 мин., пробуждение около минуты; бесплатный Render Postgres истекает через 30 дней, поэтому не выбран. Квоты Neon и хостинга проверить перед публикацией. Vercel Hobby ограничен личным некоммерческим использованием. Карта загружает OSM тайлы через интернет. Бюджет 0 ₸ не гарантирует постоянную доступность/масштабирование.

## Docker Compose
Создайте `.env`, задайте `POSTGRES_PASSWORD` локально, затем `docker compose up --build`. Том `postgres-data` сохраняет БД; удаление тома удалит данные. Приложение: http://localhost:5173 . Docker на этом компьютере может отсутствовать; конфигурация не считается проверенной без запуска.

## Основные ограничения MVP
- Полевых данных Павлодара нет; невозможно подтвердить реальную деградацию, острова тепла и численность населения. Неизвестные факторы отмечены.
- Экологические и биологические оценки нуждаются в проверке дендрологом; охлаждение в °C не выдумывается.
- Схема посадок иллюстративная, не учитывает инженерные сети/нормативные отступы. Отображается до 1000 точек.
- Интерфейс, причины подбора, риски, формулы, календарь, ошибки API и PDF/Excel поддерживают RU/KZ. Общий словарь — `shared/messages.json`; названия пользователя и история переписки сохраняют исходный текст. Технические ключи административного JSON не переводятся.
- Загрузка KML поддерживает Polygon/Point, Shapefile — один набор с .prj. Импорт проверяет границы, геометрию, объём и пересечения; публикация не подтверждает достоверность исходных измерений.
- Резервное копирование внешней БД и обслуживание выполняет владелец. Автоматического production-backup в приложении нет.

## Карта и ассистент: обновление 29.10.2026
На карте отдельные фильтры: **«Уже озеленено»** (8 парков/скверов OSM, зелёный контур) и **«Предлагается посадка»** (4 открытых территории OSM, оранжевый пунктир). Кандидаты требуют обследования; их статус не подтверждает отсутствие деревьев или разрешение на работы.

Нажмите зону: откроются краткая карточка, площадь, источник, **«Спросить ИИ»** и переименование. Кнопка AI переносит зону в чат и подготавливает вопрос; отправка вручную. Название и статус выбранного участка видны вверху чата, там же можно сменить участок или вернуться на карту. Диалоги хранятся раздельно по участкам.

Переименование поддерживает RU/KZ и варианты «Зелёный двор», «Сквер у дома», «Зелёная полоса вдоль дороги», «Новый участок озеленения». Название гостя сохраняется в этом браузере, пользователя — в аккаунте. OSM и общий каталог не меняются. Пользовательский нарисованный контур сохраняется локально; чтобы перенести полный план на другой компьютер, сохраните проект в аккаунте.

Реальные контуры доступны без повторных обращений к Overpass. Для обновления источника вручную: `python scripts/fetch_osm_zones.py`, затем `python scripts/prepare_osm_zones.py`, проверить новые контуры и перезапустить API. Эти скрипты не выполняются на каждом открытии карты.

## Мастер, язык и адресные ориентиры
Пункт «Планирование» открывает `/start`: участок → цель и бюджет → предварительный результат. Четыре цели: тень, территория у дороги, детская территория, простой уход. Генерация использует детерминированные расчёты и не расходует AI-квоту. Из результата доступны сохранение, точная настройка `/plan` и обсуждение выбранной зоны. Бюджет 0 обрабатывается явно; черновик мастера переживает обновление страницы. Изменение расчётных параметров в подробном плане сбрасывает прежний результат мастера.

У 12 зон показаны ближайшие улицы на двух языках: на карте, в карточке, списке чата и мастере. Это ориентиры по OSM, а не почтовые/кадастровые адреса. Можно искать участок по названию или улице. Обновление ориентиров: `python scripts/fetch_osm_streets.py`, затем `python scripts/label_zone_addresses.py`. Источник и дата сохранены в данных; пользовательские названия имеют приоритет.

Язык PDF/Excel выбирается по текущему языку интерфейса (`Accept-Language`). Язык нового ответа ИИ передаётся явно; существующая история не переписывается. Названия месяцев заданы явно, чтобы календарь работал и в браузерах без казахской локали Intl.

## Спутниковый мониторинг 2020–2026

Единая карта `/map?mode=changes` (также старый адрес `/monitoring`) сравнивает медианные летние NDVI-композиции настоящих Sentinel-2 L2A. По умолчанию используется проверенная административная AOI Павлодар Г.А. (OSM relation 5501700, 630,595215 км² WGS84; 630,376993 км² EPSG:32643), включая подчинённые и незастроенные территории. Пригодны для сравнения 99,69759% пикселей; пробелы 0,30241% не заполняются. Старый центральный пилот сохранён и выбирается, если городские продукты отсутствуют. Переход в класс растительности включает траву и кустарники и не доказывает посадку или вырубку деревьев.

Подготовка данных выполняется отдельно от API:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe scripts/build_monitoring.py
```

Pipeline бесплатно ищет сцены через Earth Search, читает только нужные COG-окна B04/B08/SCL, проверяет радиометрическое смещение, маскирует качество и формирует общую 10 м сетку EPSG:32643. По умолчанию выбираются два наблюдения на месяц (июнь, июль, август) каждого года; для сравнения нужно минимум два пригодных наблюдения каждого года на пиксель. SCL имеет исходное разрешение 20 м и переносится ближайшим соседом. Загрузка полных сцен при HTTP-запросах отсутствует.

Продукты и исходный каталог сохраняются в игнорируемой Git папке `backend/storage/monitoring`: NDVI/count/delta/changes GeoTIFF, GeoJSON изменений, footprint, `selected-scenes.stac.json`, `manifest.json` с идентификаторами, датами, облачностью, radiometric audit и SHA256. В свежем checkout без этих файлов интерфейс покажет честный статус недоступности. Для другого расположения задайте `MONITORING_DATA_DIR`. Воспроизводимый запуск с сохранённым STAC-каталогом поддерживается флагом `--catalog`; форматы/ограничения описаны в [MONITORING_PLAN.md](MONITORING_PLAN.md) и [API](docs/MONITORING_API.md).

Доступны слои 2020/2026, карта переходов, сравнение ползунком, выбор OSM-зоны, прозрачность, масштаб и регулируемый порог NDVI (0,10–0,90; исходный 0,30). Площади и средние считаются только по общим пригодным пикселям; отсутствующие показатели остаются пустыми. Упрощённый GeoJSON предназначен для отображения, площади считаются по исходному растру.

PDF/Excel на RU/KK включают выбранную территорию, порог, результаты, карту, NDVI и источники. Кнопка обсуждения готовит запрос ИИ с серверным инструментом `get_vegetation_change`; реальные числа и ограничения заново берутся сервером по ID зоны. Просмотр и расчёты не расходуют квоту ИИ. Статусы зон автоматически не меняются.

Проверки: `python -m pytest -q -p no:cacheprovider`, `npm test`, `npm run build`. Для независимой повторной проверки настоящих COG-пикселей задайте `MONITORING_VERIFY_REMOTE=1` при запуске `tests/test_monitoring_real.py`; это только чтение открытых источников, не облачный ИИ. Временные синтетические массивы используются исключительно в unit-тестах и не попадают в рабочий набор.


Городской набор: `python scripts/fetch_city_scenes.py --download`, затем `python scripts/build_city_monitoring.py`. Исходные DN и 24 сцены сохраняются отдельно в `backend/storage/monitoring-city`; обработка блочная, итоговые артефакты около 84,73 МБ. Для автоматического выбора оставьте `MONITORING_DATA_DIR` пустым. Проверка реальных продуктов — `tests/test_city_real.py`; повторное чтение оригинальных COG включается через `MONITORING_VERIFY_REMOTE=1`. Проверка RU/KK PDF/Excel города и зоны: `python scripts/verify_city_reports.py`; для необязательного рендера нужен `pypdfium2`. Данные из Git исключены: свежий checkout без загрузки не объявляет спутниковые показатели готовыми.
