# EcoLogicDev 4.0 — архитектурные контракты

Дата: 29.10.2026. Основа — существующий React/TypeScript/Vite + Leaflet + FastAPI/SQLite. Миграция стека отменена; проверенные формулы планировщика, вход/права/квоты ИИ сохраняются. Публикация требует отдельного подтверждения.

## Аудит текущего состояния

- `App.tsx` владеет выбранным участком, `AnalysisInput`, результатами и проектом; `zoneModel.ts` обеспечивает стабильные ID, геометрию и сохранение выбора.
- `MapView.tsx` обслуживает OSM-зоны, полигон и схему посадок. `MonitoringMap.tsx` — второй независимый Leaflet; его функциональность переносится в общую карту, не добавляется третий движок.
- `/monitoring` читает реальные Sentinel-2 композиции центра: 12 сцен, 10 м, общая маска, RU/KK отчёты и серверный инструмент. Эти данные сохраняются как центральный пилот до подтверждения городской обработки.
- `backend/monitoring/pipeline.py` пока ограничен прямоугольником и одним MGRS-тайлом. `service.py` кеширует целые растры до 2 млн пикселей. Для города эти ограничения нужно заменить проверенной AOI и ограниченной блочной обработкой.
- Git пока без базового коммита: работа ведётся в независимых областях файлов, без reset/clean и удаления пользовательских данных.

## Контракты интерфейса

1. `UnifiedMapWorkspace` использует существующий `MapView` как единственный Leaflet-движок в рабочем пространстве. Меняются слои/панели, экземпляр карты и выбор сохраняются.
2. URL: `/map?mode=territories|satellite|changes|planning|analysis&zone=<id>&year=2020|2026&threshold=0.3&compare=1`. Неизвестные параметры сохраняются; значения валидируются.
3. Старые `/monitoring`, `/problems`, `/priorities` перенаправляются в соответствующий режим с сохранением `zone` и порога. `/plan`, `/start`, `/plants`, `/analytics` остаются совместимыми инструментами; повторные карты в их содержимом убираются. Главное меню: карта, планирование, аналитика, ИИ, проекты.
4. Источник выбора — root `AnalysisInput.zone_id`/geometry и URL. Режим карты не изменяет site/budget/plants и не очищает выбор. Если слой скрывает выбранный объект, показывается уведомление и сохраняется карточка.
5. Общие инструменты: поиск, слой/масштаб, выбор, рисование/редактирование, прозрачность, легенда/источники. В satellite/changes: год, NDVI/качество, сравнение-разделитель. Панели имеют desktop collapse и mobile bottom sheet.
6. Единая карточка читает статистику `/api/monitoring/zones/{id}`; null и неполное покрытие показываются явно. Наблюдения не изменяют статус OSM-зоны. Кнопки передают существующие root callbacks для планирования, ИИ и сохранения.

## Контракты геоданных

- `backend/assets/pavlodar-boundary.geojson`: проверенный Polygon/MultiPolygon WGS84 административного объекта, с OSM ID/URL, датой, лицензией, admin_level, объяснением выбора. Place-полигон города и граница области не считаются автоматически административной границей города.
- Обработка EPSG:32643, шаг 10 м, маска точной городской AOI по центрам пикселей. B04/B08 и SCL; SCL 20 м переносится ближайшим соседом, без искусственной детализации.
- Каталогизация STAC с пагинацией и всеми MGRS-тайлами, пересекающими AOI. Отбор сцен по сезону и тайлу; идентификаторы, даты, облачность и radiometric audit обязательны.
- Два года на одной сетке; медиана пригодных наблюдений; минимум два наблюдения каждого года для сравнения. NoData не заменяется нулём или интерполяцией.
- Блочная обработка с возобновляемым кешем и атомарным manifest. Центральный набор не перезаписывается до успешной валидации городского. Большие пиксельные GeoJSON не генерируются; веб использует растровые тайлы.
- `manifest.json`: scope `administrative_city` только при подтверждённой AOI; boundary metadata/hash, площадь км², grid, scenes по годам/тайлам, пригодность каждого года и совместная, размер/хеши продуктов и пробелы.

## Backend/AI/отчёты

Сохраняются шесть `/api/monitoring/*` endpoints. Метаданные расширяются `aoi`, `coverage`, `scope`; прежние поля совместимы. Тайлы дополнительно NDVI и качество, с одной общей маской для сравнения. Статистика имеет null при отсутствии общих пикселей. Кеш ограничен; при больших растрах статистика/тайлы читаются окнами, не загружают все сцены.

`get_vegetation_change` получает серверные цифры по ID, периоду и порогу; территория и геометрия согласуются. Бесплатные провайдеры/серверный ключ/Retry-After/квоты сохраняются. Формулировки «весь город» допустимы только при наличии подтверждённой административной AOI и раскрытых процентах покрытия. PDF/Excel получают ту же AOI/маску/порог и RU/KK.

|---|---|---|
| 1 | Координатор/root | контракты, PROGRESS, App integration, зависимости, финальные проверки |
| 2 | UI/UX | `src/UnifiedMapPanels.tsx`, `src/unifiedMap.css` |
| 3 | Frontend | `src/UnifiedMapWorkspace.tsx`, `src/unifiedMapModel.ts`, `src/MapView.tsx`, state tests |
| 4 | Границы | boundary GeoJSON/metadata, `scripts/fetch_pavlodar_boundary.py`, boundary tests |
| 5 | Спутниковые данные | `backend/monitoring/city_catalog.py`, scene catalog/cache, MONITORING_DATA_SOURCES |
| 6 | GIS/NDVI | `backend/monitoring/city_pipeline.py`, city products/cache, coverage tests/document |
| 7 | Backend | `backend/monitoring/service.py`, `api.py`, API tests — после согласования city manifest |
| 8 | Аналитика/отчёты | `backend/monitoring/reports.py`, report tests |

Одновременно доступны максимум три дочерних агента. Роли запускаются волнами; общий файл не редактируется двумя исполнителями. Готовность агента не заменяет проверку интеграции. Если технические/аккаунтные лимиты препятствуют запуску, это фиксируется без заявления о выполненной работе десятью агентами.

## Волны и gates

1. Аудит/ресурсы/граница/контракты → UI, frontend, границы.
2. Sentinel-каталог + блочная городская обработка + API. По завершении волны — PROGRESS, backend tests, npm test/build.
3. Отчёты + AI + независимый QA, совместимость ссылок/состояния/карт и 390×844.
4. Переключение рабочего набора на городской только после hash/grid/AOI/coverage/NoData проверок. Итоговые документы раскрывают площадь, сцены/даты, размеры, покрытие и ограничения. Неполное покрытие не объявляется полным анализом города.

Ресурсы при старте: RAM 16 ГиБ, свободно около 3,3 ГиБ; диск C: около 175 ГиБ свободно. Память ограничивает размер блоков и кешей; число сцен/байтов уточняется после получения административной AOI и STAC-каталога.
