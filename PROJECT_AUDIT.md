# Повторный аудит EcoLogicDev после Antigravity

Дата: 30.10.2026. Сохранены существующий MVP, React/Leaflet, FastAPI/SQLite, формулы планировщика и реальные спутниковые продукты. Изменения Antigravity не откатывались. Публикация не выполнялась.

## Подтверждённые проблемы и исправления

| Приоритет | Проблема | Исправление / доказательство |
|---|---|---|
| Высокий | Городской pipeline искал checkpoint в каталогах **других** fingerprint. При изменении сцен, AOI, сетки или кода мог получить старые данные того же размера. | Удалён межверсионный fallback; возобновление только внутри текущего fingerprint. Регрессионная проверка в `test_city_pipeline.py`. Существующий набор отдельно сверен с DN, масками и выходными пикселями. |
| Высокий | Обзор всей административной AOI отдалял карту ниже zoom 11, а клиентские спутниковые слои и API работали только с zoom 11. На масштабе города спутниковое покрытие исчезало. | Клиент/API поддерживают zoom 8–19. Реальные PNG при zoom 8, 9, 10 проверяются на непустую альфу в `test_city_real.py`. |
| Высокий | npm выявил устаревший транзитивный `@grpc/grpc-js` 1.9.16 внутри Firebase. | Закреплена исправленная 1.13.6 через override, lockfile обновлён без install-скриптов. Итоговый npm audit: 0 известных уязвимостей. [Пояснение разработчика](https://github.com/advisories/GHSA-m9gg-hp2v-232j), [второе исправление](https://github.com/advisories/GHSA-f596-whhp-79r4). Проект не использует Firestore; серверные gRPC-сценарии уязвимости здесь не включены. |
| Средний | AI принимал `scope=zone` за признак центрального пилота даже при использовании городского набора. | Источник определяется по проверенным AOI/coverage; `dataset_scope` отделён от области выбранной зоны. ИИ не получает геометрию AOI и не выдаёт цифры зоны за итог города. Добавлен тест. |
| Средний | Панель сравнения перекрывала поиск; на телефоне открытая панель занимала почти всю карту, скрывала легенду и масштаб. | Разведены строки поиска и сравнения; мобильная панель первоначально свёрнута, легенда и масштаб подняты. Проверено на реальном браузерном viewport 390×844 на RU/KK. |
| Средний | Легенда качества обещала прозрачный NoData, хотя недостаточные наблюдения показывались серым, и использовала расплывчатое слово «достоверность». Цвет NDVI не совпадал с сервером. | Показаны реальные классы числа наблюдений: <2, 2–3, ≥4; минимум двух сезонов. Градиент согласован с RGB сервера. Подписи сравнения не называют слой качества NDVI. |
| Средний | `.env.example` принудительно выбирал центральный пилот даже при готовом городе. | По умолчанию путь пустой, используется проверенный автоматический выбор. Явный пользовательский override сохранён. |
| Средний | Документация содержала неверную облачность сцен, «3 страницы» вместо 4, «распределение NDVI» вместо двух средних и безусловное заявление о полной готовности. | Облачность переписана из manifest; уточнены виды графиков, API/кеши/папки и границы проверок. Итоговые заявления ниже имеют воспроизводимые команды. |

## Реальные спутниковые данные

- Dataset `fce35299b4f7c8a75d01c972`, 24 сцены, MGRS 43UFT/43UFU, 72 исходных фрагмента B04/B08/SCL.
- Граница OSM relation 5501700: 630,595215 км² WGS84, 630,376993 км² EPSG:32643; это городская администрация с подчинёнными и незастроенными территориями.
- Сетка 4152×4039, 10 м; внутри AOI 6 303 776 пикселей. Итоговые артефакты 84 733 628 байт.
- Пригодность 2020: 99,83058%; 2026: 99,79062%; общая: 99,69759%. 19 063 пикселя / 190,63 га NoData сохранены.
- NDVI ≥0,30 на общей маске: 25 113,03 → 23 936,66 га. Прирост 4 098,13 га, потери 5 274,50 га, баланс −1 176,37 га. Это не доказательство вырубки, посадки или числа деревьев.
- Все SHA-256 итоговых артефактов и 72 исходных фрагментов совпали. **Каждый пиксель** `changes` и `delta_ndvi` сверен независимым расчётом по двум NDVI/count и точному полигону. Вне AOI NDVI=NoData и count=0; все 12 зон имеют пригодные пиксели.
- На выборках севера/стыка тайлов/юга повторены радиометрия, SCL-маска, мозаика одной даты, медиана и число наблюдений из исходных DN. Дополнительно перечитаны небольшие окна оригинальных публичных COG обоих годов и обоих тайлов; значения совпали с кешем.
- Продукты не пересоздавались и не заменялись тестовыми данными. После исправления checkpoint следующий запуск с изменённым fingerprint пересчитает блоки; старые файлы остаются доступными.

## Проверки

Команды выполняются из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --disable-warnings
npm.cmd test
npm.cmd run build
npm.cmd audit --omit=dev
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/verify_city_reports.py
```

Опциональные сетевые проверки запускаются отдельно:

```powershell
$env:MONITORING_VERIFY_REMOTE='1'
.\.venv\Scripts\python.exe -m pytest tests/test_city_real.py -k remote -q
.\.venv\Scripts\python.exe -m pytest tests/test_monitoring_real.py -k cog_pixel -q
```

Итог: **67 backend passed / 2 сетевых skipped**, **20 frontend passed**; каждый из двух сетевых тестов отдельно **passed** с включённым сетевым флагом. Production build успешен (8,92 с, JS 382,17 КБ gzip); `pip check` без конфликтов; npm audit без известных уязвимостей. Проверка на наличие OpenRouter-секрета в исходниках клиента и собранном `dist` совпадений не нашла.

API-тесты проверяют владение проектами/отчётами, CSRF, роли, приватность названий и истории, несоответствие ID/геометрии, бесплатные модели/лимиты и ошибки. Добавлено отклонение ложных localhost-доменов и блокировка произвольного loopback Origin в production. Разрешение любых локальных портов Antigravity оставлено только для development.

PDF/Excel сформированы для города и зоны на RU/KK. Числа совпадают с сервисом, все 24 ID сцен присутствуют; каждый PDF имеет 4 страницы. Все 16 страниц отрендерены; выполнен выборочный визуальный просмотр таблиц, карты, графика и источников. Это график двух средних сезонных NDVI, без интерполяции промежуточных лет. QA-артефакты: `output/qa/city-reports` (не включаются в Git).

Браузером проверены один Leaflet-контейнер, RU/KK, отсутствие горизонтального переполнения при 390×844, сворачивание панели, drag шторки (50→66,9% с сохранением в URL), клавиатура, выбор зоны, карта→AI с подготовленным вопросом→карта с тем же ID/порогом. Исправленный обзор всей AOI показывает реальный слой изменений на карте; ошибок в браузерной консоли нет. Скриншоты: `output/qa/audit-mobile-kk.jpg`, `output/qa/audit-city-desktop.jpg`.

## Что этот аудит не подтверждает

- Публикацию и production-вход на разных доменах. `SameSite=lax` в текущем session cookie требует отдельной проверки вместе с окончательной схемой доменов/API proxy до публикации.
- Реальный вход Firebase/доставку email: внешняя учётная запись не подключалась. Локальные роли/сессии проверены тестами с изолированной SQLite, пользовательская БД не использовалась для тестовых аккаунтов.
- Живой новый ответ OpenRouter: облачные запросы в этом аудите не отправлялись. Передача контекста и обработка бесплатных провайдеров проверены тестами; ключ остаётся только в памяти локального API.
- Полный ручной сценарий рисования/редактирования и все комбинации устройств. Движок, существующие тесты геометрии и сборка сохранены; это не заявление об отсутствии любых оставшихся ошибок.

Крупный клиентский JS остаётся около 1,28 МБ / 382 КБ gzip. Это кандидат на последующее разбиение по маршрутам, без необходимости переписывать MVP.
