# EcoLogicDev 4.1 — контракты и порядок работ

База: локальный checkpoint `0dddcb5` проверенного MVP. Стек/формулы/данные 4.0 сохраняются. Публикация не выполняется.

1. P0 карта: серверная сводка шести показателей; явный scope city/zone; единый источник выбора и независимый viewport. Null не превращается в 0. Переключение режима не меняет область анализа.
2. Проекты: необязательный валидируемый `map_state` (mode/year/layer/threshold/opacity/swipe/compare/scope/zone_id/center[lat,lon]/zoom). Аддитивная миграция сохраняет старые проекты; владение/CSRF прежние.
3. Сценарии: новые серверные вычисления вызывают прежний `analyze`. Базовый сохраняет состав новых посадок; усиленный меняет только полив/интенсивность; дополнительные посадки — явный +20% количеств с проверкой бюджета/площади и раскрытием превышений. Фактическая инвентаризация существующих деревьев неизвестна. Геометрия/почва/бюджет/горизонт одинаковы.
4. AI: факты/шесть разделов/источники/действия формирует сервер; модель объясняет и не рассчитывает числа. Память на сервере изолирована owner+zone, содержит fingerprint плана и краткие сценарии. Гостевой контекст ограничен текущей сессией. Ошибки/квоты дают явно подписанную детерминированную сводку. Разрешённые действия строятся клиентом из типизированного enum и ID, не из URL модели.
5. Рейтинг: только измеренные loss/common area, net change, common fraction; отдельная эвристика очереди полевого обследования, без диагноза деградации. Исходный индекс планировщика остаётся отдельным.
6. RGB: настоящие B04/B03/B02 **тех же** 24 сцен; SCL и радиометрия; блочная сезонная медиана. Отдельный `rgb-manifest.json` привязан к dataset_id и исходной сетке. Исходные NDVI/count/manifest не переписываются. До проверки обоих лет RGB недоступен, а не заменяется изображением другого источника.
7. Проверки по этапам: backend/frontend/build; затем полный изолированный пользовательский сценарий RU/KK, браузер 390×844, реальные RGB/NDVI данные и отчёты. Готовность отмечается только после фактической проверки.
